Decide how one candidate profile relates to retrieved user-profile timeline entries.

Compare by object-state units: each unit is an explicit object plus its state/relation, e.g., "likes eggs" or "dislikes coffee". A profile may contain multiple units. Missing time means current unless explicitly past-only. Compare explicit objects only; do not treat broad categories as object containment.

Actions:
- confirm: candidate units are fully entailed by a current profile and add no new object, state, detail, reason, condition, or time.
- update_current: use only when the candidate changes the state/relation of the same explicit object, or adds/modifies details about the same explicit object. Preserve unchanged old units; do not merge unrelated or compatible candidate-only units.
- update_history: candidate describes an earlier or past-only state that should not replace the current profile.
- new: candidate should be stored as a new profile.

Overlap rules:
- Candidate fully covered by old profile with no new info -> confirm. 
- Same object only, with state conflict or same-object detail change -> update_current. 
- Partial object overlap without conflict -> new. Do not update or merge old profiles. 
- Partial object overlap with conflict on a shared object -> update_current only the conflicting old profile and modify only the conflicting part; update_current the conflicting old profile by modifying only the conflicting shared object and preserving unchanged old units; also set new_profile to true and set new_content to the whole new profile. 
- Same-domain, related, or different objects -> new. 
- If unsure, choose new. 

Examples:
- old "likes eggs and greens", candidate "likes eggs" -> confirm. 
- old "likes eggs and milk", candidate "likes eggs and greens" -> new: "likes eggs and greens".
- old "likes eggs and greens", candidate "dislikes eggs and milk" -> update_current: "dislikes eggs and likes greens"; new_content: "dislikes eggs and milk".
- old "likes dogs", candidate "likes animals" -> new.
- old "likes coffee", candidate "liked coffee in 2020" -> update_history.

Return JSON only:
{
  "decisions": [
    {
      "profile_id": "P1",
      "action": "confirm|update_current|update_history",
      "updated_content": "",
      "target_version_id": "",
      "evidence": ["F1"]
    }
  ],
  "new_profile": true,
  "new_content": ""
}
